# RESULTS

**Status: pipeline cost/latency are measured on real runs; verifier accuracy is measured on 116 real claims with LLM-drafted, author-reviewed labels (single annotator, no kappa) and on 24 synthetic cases.** All headline numbers are regenerated by `make eval` (`python scripts/make_results.py`) into `evals/results.json` and the README table; CI runs `--check`. Nothing here is a claim until a row below has a command, a data file hash and a number. Synthetic or author-labeled data is labeled as such and is diagnostic only.

## Methodology
- Positive class = "kept" (verifier says `supports`). **precision** = P(gold supports | kept); **retention** = P(kept | gold supports). Always read together: dropping everything gives high precision and zero retention.
- 95% CIs: percentile bootstrap over claims, 2000 resamples, seed 0 (`scripts/eval_metrics.py`). Claims from one report are correlated, so these CIs are optimistic until grouped resampling is added. When precision is k/k on few claims the bootstrap collapses to [1, 1], so a Wilson interval is reported too.
- Every report records the predictions file SHA-256 and git HEAD.
- **false-acceptance rate (FAR)** = P(kept | gold not supports) is the primary safety metric; FRR = 1 - retention.

## Measured

### 1. Verifier on 24 hard cases (live Stage 2)
Data: `evals/hard_cases.csv`, **synthetic, labeled by the author** (9 supports / 2 partial / 13 unsupported); categories: paraphrase, rounding, negation, hedging, multi-hop, overstated, adversarial snapshot. Diagnostic only, not real-world precision.
Command: `DATABASE_URL=... python scripts/eval_hard_cases.py --stage2` then `python scripts/eval_report.py evals/eval_runs/hard_cases_full_predictions.csv`.
Verifier `qwen/qwen3.8-27b` on Groq, cache disabled (0 cache hits), 17 provider calls (7 rows were dropped by Stage 1 before any LLM call), 11,039 provider-reported tokens, $0.0063 modeled.

| Arm | Accuracy (3-class) | Macro-F1 |
|---|---|---|
| Full verifier (Stage 1 + Stage 2) | 0.750 | 0.647 |
| Stage 1 only | 0.417 (0.458 on current code after the hedged-rounding rule; `make eval`) | 0.287 |
| Best string baseline (claim-vs-span fuzzy, threshold 90/95) | 0.500 | 0.271 |
| Always "unsupported" (label prior) | 0.542 | - |

Kept-claim view (kept = verdict `supports`): precision 5/5 = 1.000 (**Wilson 95% CI 0.566-1.000**; the bootstrap gives a degenerate [1, 1], ignore it), retention 5/9 = 0.556 (Wilson 0.267-0.811). No unsupported claim was kept; the cost is false drops.
Errors (6/24): paraphrase 1 and 3 dropped; rounding 7 ("about 12" vs 12.4) and 9 dropped by Stage 1 fact tokens; partial 6 called unsupported; overstated 21 called partial (would go to rewrite, not shipped as-is).

### 2. Verifier on 116 real claims (LLM-drafted, author-reviewed labels)
Data: `evals/real/dev_label_sheet.csv` (73) and `test_label_sheet.csv` (43): every claim with a resolved span from the 10
real runs below, shuffled, blind to verdicts. Frozen by SHA-256 in `evals/real/*.freeze.json`; `make eval` refuses to run if
either sheet changes. `test` is the held-out split: nothing is tuned on it.
Predictions: the pipeline's **shadow verdicts recorded at run time** (Stage 1 + live Stage 2), joined by (job, claim_id).
Command: `make eval` (no network). Numbers: README table / `evals/results.json` `real_claims`.

**Label provenance (read before quoting any number):**
- Drafted by an LLM, then reviewed and corrected by the author (AK) on 2026-11-06. Drafting model: _not recorded yet_.
  If it is the same model family as the verifier, labels may be biased toward agreeing with it.
- One annotator. `evals/real/second_annotator_kappa_30.csv` (30 rows) is empty, so there is no Cohen's kappa.
- The verdicts come from runs at older commits (569fc72 and nearby). They predate pgvector retrieval, the 60% writing
  cap and the hedged-rounding / scale-word Stage 1 changes, so they measure that verifier, not the current one.
- CIs resample claims i.i.d.; claims cluster by job (10 jobs), so the intervals are optimistic.
- Positives dominate (84 of 116 gold `supports`), so FAR rests on 32 negatives (12 in the test split) and its interval is wide.

### 4. PDF retrieval, E1-E4 (QASPER)
Data: `evals/qasper/gold.json` (SHA-256 `54da6f57...`), built by `python scripts/build_qasper_gold.py --papers 60` from
QASPER dev v0.3 (Allen AI, CC BY 4.0): the first 60 sorted paper ids with a usable arXiv PDF, 166 questions, 286 gold
spans. Gold = QASPER's **human-annotated evidence paragraphs**, aligned to our parsed PDF text (82 exact, 204 fuzzy >= 90;
74 of 360 evidence strings could not be aligned and were dropped, so 25 questions have no gold and are excluded).
Setting: **all 60 papers in one notebook**, so a question competes with every paper's chunks. This is harder than the
usual one-paper QASPER setting, which is why absolute recall is low; the per-paper setting is not measured.
Nothing was tuned on these questions (candidates 20, RRF k 60, 480-token chunks, models fixed in advance).
Command: `python scripts/run_retrieval_eval.py --database-url postgresql+asyncpg://...` (local models, no LLM, $0).
Recorded at git `7edcf79` (clean tree) in `evals/retrieval_results.json`; two runs gave identical metrics.

| Exp | Chunks | Retrieval | recall@5 | recall@10 (95% CI) | MRR@10 | nDCG@10 | p50 / p95 latency |
|---|---|---|---|---|---|---|---|
| E1 | fixed 350 words | dense | 0.225 | 0.270 (0.208-0.338) | 0.183 | 0.179 | 48 / 57 ms |
| E2 | structure-aware | dense | 0.228 | 0.308 (0.245-0.379) | 0.192 | 0.195 | 51 / 56 ms |
| E3 | structure-aware | dense + full-text, RRF | 0.220 | 0.323 (0.256-0.391) | 0.188 | 0.192 | 84 / 125 ms |
| E4 | structure-aware | E3 + cross-encoder rerank of top 20 | 0.281 | 0.375 (0.305-0.445) | 0.238 | 0.241 | 2,290 / 2,568 ms |

Paired bootstrap deltas on recall@10 (same questions): E2-E1 +0.038 (-0.009 to +0.089) and E3-E2 +0.015 (-0.029 to
+0.060) are **not distinguishable from zero**; E4-E3 +0.053 (+0.019 to +0.088) and E4-E1 +0.105 (+0.055 to +0.156) are.

Decision: keep `hybrid+rerank` as the default (`app/retrieval.py`). The reranker is the only component with a measured
gain; hybrid alone is not shown to help, and is kept only as the candidate generator for the reranker (E4 vs
dense+rerank is not measured). Cost: rerank adds ~2.2 s per query on this CPU (12 cores, no GPU); latency is from one
machine and is not portable. Recall is a ceiling for answer quality, not answer quality: chat answers are not measured yet.

### 5. Retrieval-score abstention for chat, E6a (negative result)
Question: can the top cross-encoder score tell "this notebook can answer" from "it cannot" before any LLM call?
Command: `python scripts/run_abstention_eval.py --database-url postgresql+asyncpg://...` (local models, no LLM, $0).
Recorded at git `2804bd2` (clean tree) in `evals/abstention_results.json`.
Design, fixed before any score was seen: papers are assigned by SHA-256 of their id, 1 in 3 OUT of the notebook (47 in,
13 out), and independently 50/50 into dev and test by paper. Answerable = gold questions about an IN paper;
unanswerable = gold questions about an OUT paper (the notebook holds other NLP papers, so these are near-misses);
plus QASPER questions about IN papers that every annotator marked unanswerable (only 10, reported as counts).
Policy: answer iff top score >= t, t chosen on dev to keep >= 90% of answerable questions (t = -3.945, a logit).

| Split | False abstention on answerable | Abstains on unanswerable (out of notebook) | In-paper unanswerable abstained | AUROC |
|---|---|---|---|---|
| dev (threshold chosen here) | 4/49 = 0.082 (Wilson 0.032-0.192) | 4/18 = 0.222 (0.090-0.452) | 0/2 | 0.670 |
| **test** | **13/84 = 0.155 (0.093-0.247)** | **3/15 = 0.200 (0.070-0.452)** | 1/8 | **0.595** |

Decision: **the score gate stays off** (`CITEGUARD_ABSTAIN_MIN_RERANK_SCORE` unset). On held-out papers it refuses
15.5% of answerable questions to catch 20% of unanswerable ones; AUROC 0.60 is close to chance. Abstention therefore
rests on the model's own `abstain` flag and on the verifier dropping unsupported sentences, which are not measured yet
(E5/E6b need live LLM runs). Caveats: 15 test negatives give a wide interval; "answerable" means the evidence is in the
notebook, not that retrieval found it.

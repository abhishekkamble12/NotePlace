## Week 1 (Dec 4-10): Foundation + multimodal ingestion

**Goal:** documents of every supported type become correctly routed, chunked and searchable, and the parser is measured.

**D1: Schema + auth**
- Alembic migration for the Phase 2 tables (spec section 7): users, notebooks, sources, pages, figures, chunks, summaries, citations, outputs, notes.
- MinIO in docker-compose; storage helper for raw files and page images.
- Email + password auth (bcrypt, JWT). Every repository function takes `user_id`.
- Isolation test scaffold: two users, one test per endpoint, added to as endpoints appear.

**D2: Test set (before the parser)**
- 6 notebooks, 2-4 documents each, including scanned pages, tables and charts.
- About 60 questions across types: lookup, multi-hop, summary, comparison, table-only, chart-only, unanswerable (about 8).
- Gold answers as page + character span (not chunk ID).
- Parser gold: 20-30 pages hand-transcribed or with tables checked cell by cell.

**D3: Docling ingestion + page router**
- `POST /notebooks/{id}/sources` (file, URL, text) → arq `ingest_source` job; SHA-256 dedupe.
- Docling for PDF, DOCX, PPTX, HTML; PyMuPDF to check each page's text layer and render page images.
- Route each page: text layer → Docling text; no text → OCR. Store `route`, `parser`, `confidence`, `parse_ms` per page.

**D4: OCR + tables**
- PaddleOCR for scanned pages; low-confidence pages flagged (vision OCR fallback stays optional).
- Tables become Markdown chunks (never split) with a 1-2 line summary.
- Source status updates: `uploaded → parsing → chunking → embedding → ready | failed` with error reasons.

**D5: Chunking + indexing**
- Structure-aware chunking with page and character offsets; contextual header per chunk.
- bge-small embeddings, HNSW index, `tsvector` + GIN index.
- Hierarchical summaries (chunk → section → source), stored once for the output graph.

**D6: Parser eval**
- `evals/parser.py`: character error rate per OCR route, table cell accuracy.
- `evals/retrieval.py`: Recall@5 and MRR by question type. Run ablation configs 1-4.

**D7: Buffer + CI**
- CI: ruff, mypy, pytest (isolation tests included), cached retrieval eval on a small subset.

**Exit check:** parser metrics and configs 1-4 in the results table.

## Week 2 (Dec 11-17): Retrieval + grounded chat

**Goal:** a user asks a question and gets a streamed answer where every sentence links to its highlighted passage, or a refusal.

**D8: Figure captions**
- Docling figure crops → Ollama vision model caption → indexed as `figure_caption` chunks. Config 5.

**D9: Hybrid retrieval + reranker**
- Dense + full-text search fused with reciprocal rank fusion (config 6); `bge-reranker-base` (config 7); contextual headers on/off (config 8).
- Decide what stays based on Recall@5 and latency, and write the decision in the README.

**D10-D11: Chat graph**
- LangGraph: `classify → retrieve → rerank → answer → cite_check → verify → respond | refuse`.
- Answer as structured `[{sentence, chunk_ids, quote}]`; streamed over SSE (tokens, then citations, then done).
- Reuse the Phase 1 verifier for `cite_check` and `verify` (sampled at 30% in the demo, always on in eval).
- Refusal threshold chosen on the unanswerable questions, and documented.

**D12-D13: Frontend shell + citation viewer**
- React + Vite + TypeScript, three panes: Sources (with statuses and page routes), Chat, Studio (empty for now).
- Citation click opens `react-pdf` at the page with the passage highlighted; OCR'd pages show the page image beside the text.

**D14: Chat eval**
- Citation validity (must be 100%), faithfulness with judge-human agreement on 50 items, refusal accuracy, first-token latency.

**Exit check:** configs 5-8 measured; chat metrics in the results table; one full demo flow works in the browser.

---

## Week 3 (Dec 18-24): Shared output graph + reports + flashcards

**Goal:** one generation pipeline that every study feature plugs into, proven with reports and flashcards.

**D15-D16: Shared output graph**
- `select_scope → plan → generate → cite_check → verify → repair → dedupe → save → render`.
- Output-type registry: `{schema, prompts, extra_checks, renderer}`.
- `POST /notebooks/{id}/outputs` with source scope, length and difficulty; arq job; status polling.
- Record `items_generated` and `items_dropped` (with reasons) per output.

**D17: Reports**
- Briefing, FAQ, study guide, timeline as registry entries. Markdown export.

**D18-D19: Flashcards**
- Schema `{front, back, chunk_ids, quote, difficulty, topic}`; extra checks: answer leak, near-duplicate merge, count within ±10%.
- SM-2 scheduling (about 30 lines, unit-tested with known sequences); `card_reviews` table.
- `GET /flashcards/due`, `POST /flashcards/{id}/review`; review UI (flip card, rate again/hard/good/easy).
- CSV export (Anki-compatible).

**D20-D21: Output eval**
- Flashcards: validity, answer-leak rate, duplicate rate, coverage; human rating on 40 cards.
- Reports: claim faithfulness on briefing and study guide.
- Verifier on vs off for flashcards.

**Exit check:** flashcard and report metrics in the results table.

---

## Week 4 (Dec 25-31): Quiz + mind map + Studio UI

**Goal:** the study tools are complete and usable. This week includes the holiday, so it's planned light.

**D22-D23: Quiz**
- Schema `{question, options[4], correct_index, explanation, chunk_ids, quote, difficulty}`.
- Extra checks: correct option supported; every distractor unsupported (one verifier call each); options shuffled in code.
- `POST /outputs/{id}/attempts` → score and per-question feedback linking to passages. Quiz UI.

**D24: Mind map**
- Tree schema (3 levels max, about 7 children per node, leaves cited); built from section summaries.
- Rendered with `markmap` or React Flow; clicking a node shows citations or opens chat pre-filled.

**D25: Notes + Studio pane**
- Pin answers and outputs to notes; Markdown export.
- Studio pane lists all outputs with status, and opens each in its viewer.

**D26-D28: Quiz eval + buffer**
- Answer-key correctness, ambiguity rate, correct-answer position balance; human check of 30 questions.
- Mind map: leaf citation validity, coverage of section headings.

**Exit check:** all core output types work in the UI; quiz and mind map metrics in the results table.

## Week 5 (Jan 1-7): Stretch: media overviews

**Goal:** add audio and video only if weeks 1-4 are done. If not, use this week to catch up and skip to week 6.

**D29-D31: Audio overview**
- Registry entry: outline → two-host script (`Alex`, `Sam`), each turn cited → verify → repair.
- TTS per turn (Piper or Kokoro locally); `pydub` + ffmpeg join; MP3 + transcript linked to citations.
- LangGraph checkpointer so a crash does not re-synthesize finished turns.

**D32-D34: Video overview (narrated slides)**
- Slide spec `[{title, bullets[], chunk_ids, figure_id?, narration}]`, verified.
- HTML slide template → PNG with Playwright, using the documents' own figures.
- TTS per slide → ffmpeg MP4 + SRT subtitles.

**D35: Media rating**
- 10 audio and 5 video overviews rated by two people (accuracy, coherence, engagement); n stated.

**Exit check:** media generated and rated, or cut and noted in the README.

---

## Week 6 (Jan 8-15): Integrate, ship, prove

**Goal:** the two phases become one product, and anyone can see it working.

**D36: "Research the web" import**
- A notebook button runs a Phase 1 research job on a question and imports its verified sources (snapshots, URLs, fetched_at) as notebook sources. One day, because both sides already exist.

**D37: Deploy**
- API and worker on Render or Railway, frontend on Vercel or Netlify, managed Postgres and Redis, MinIO or S3-compatible storage.
- Groq for the demo with a per-notebook token cap; demo account with a pre-loaded notebook.

**D38: End-to-end tests + isolation**
- Playwright: upload → chat with citation click → generate flashcards → review a card → take a quiz.
- All isolation tests green.

**D39: Results**
- `evals/report.py` produces the final tables: parser, retrieval ablation by question type, chat, flashcards, quiz, mind map, cost and latency.
- Charts: Recall@5 per config by question type; items dropped by the verifier per output type.

**D40-D41: README + gallery**
- Architecture diagram (both phases), three guarantees, results tables, design trade-offs, limitations, one-command setup.
- Public gallery: an example notebook with its chat, flashcards, quiz, mind map and media, viewable without an account.

**D42-D43: Write-up + demo video + resume**
- Post: "Building a study notebook where every flashcard cites its source: what the verifier caught."
- 3-minute video: upload a scanned PDF, ask a chart question, click a citation, generate and review flashcards, take a quiz, import web research.
- Fill in the resume bullets in `03_notebook_spec.txt` section 14 with measured numbers only.

**Exit check:** every box in `03_notebook_spec.txt` section 13 is ticked.
